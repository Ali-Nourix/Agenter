# Agenter

**دستیار هوش مصنوعی ابزارمحور، درون Obsidian.**

یادداشت‌ها، پژوهش‌ها و نوشتار روزمره‌تان را در یک محیط کاری هوش مصنوعی کنار هم بیاورید. کنار یادداشت‌ها گفتگو کنید، از زمینهٔ آگاه از Vault استفاده کنید، وب را جست‌وجو کنید، پرامپت‌های قابل استفادهٔ مجدد اجرا کنید و پیش از اعمال تغییرات روی Vault، آن‌ها را بازبینی کنید.

> [!IMPORTANT]
> **Agenter یک افزونه است، نه سرویس هوش مصنوعی.** این افزونه به ارائه‌دهنده و مدلی متصل می‌شود که شما پیکربندی می‌کنید. باید اطلاعات دسترسی API خودتان را وارد کنید یا از تنظیمات محلی پشتیبانی‌شدهٔ Ollama استفاده کنید. قابلیت‌ها و هزینه‌ها به ارائه‌دهنده بستگی دارند.

## قابلیت‌ها

- **سه حالت گفتگو:** نوار کناری ثابت، پنجرهٔ شناور و پنجرهٔ زمینه‌ای برای متن انتخاب‌شده؛ کنار محل نشانگر یا در نقطه‌ای که یک بار انتخاب می‌کنید.
- **چند ارائه‌دهنده:** OpenAI، Anthropic، Gemini، OpenRouter، Ollama، Cloudflare Workers AI، هر سرویس سازگار با OpenAI و نشانی‌های سفارشی.
- **زمینهٔ آگاه از Vault:** یادداشت فعلی، پوشهٔ فعلی، کل Vault یا بدون زمینهٔ خودکار.
- **استفاده از ابزارها:** خواندن و جست‌وجوی یادداشت‌ها، بررسی پیوندها و فراداده، فهرست پوشه‌ها، خلاصه‌سازی محتوا، جست‌وجوی وب، دریافت نشانی‌ها و خواندن تصاویر یادداشت‌ها در مدل‌های دارای قابلیت بینایی.
- **اقدام‌های کنترل‌شده روی یادداشت‌ها:** ساخت، ویرایش، افزودن متن، جابه‌جایی و انتقال یادداشت به سطل زباله، فقط پس از مرحلهٔ تأییدی که تنظیم کرده‌اید.
- **تغییرات قابل‌بازیابی:** تغییر یادداشت‌ها یک نسخهٔ پشتیبان ایمنی در `.agenter-backups` ایجاد می‌کند و حذف از سطل زبالهٔ قابل‌بازیابی Obsidian عبور می‌کند.
- **یک گفتگوی مشترک:** پنل اصلی و پنجرهٔ زمینه‌ای تاریخچهٔ یکسانی دارند؛ می‌توانید گفتگو را در یکی شروع و در دیگری ادامه دهید.
- **پرامپت‌های سفارشی:** در تنظیمات، اقدام‌های پرامپتی قابل استفادهٔ مجدد بسازید تا در گفتگو و پنجرهٔ شناور در دسترس باشند.
- **رندر بومی Obsidian:** پاسخ‌ها، پیش‌نمایش یادداشت، بلوک‌های کد و پیوندهای داخلی با رندرکنندهٔ Markdown خود Obsidian نمایش داده می‌شوند؛ از جمله متن راست‌به‌چپ.
- **پاسخ‌دهی تدریجی همراه با وضعیت زنده:** ورود تدریجی پاسخ را ببینید، تولید را متوقف کنید و روند اجرای هر ابزار را دنبال کنید.
- **بدون سقف مستقل برای طول پاسخ:** هر پاسخ می‌تواند تا اندازه‌ای که مدل اجازه می‌دهد ادامه یابد. نوار وضعیت میزان پرشدن پنجرهٔ زمینه را نشان می‌دهد و گفتگوهای طولانی پیش از سرریز فشرده می‌شوند.
- **سازوکار سازگاری برای هر مدل:** محدودیت‌های هر مدل ثبت می‌شوند، فراخوانی ابزار از متن بازیابی یا اصلاح می‌شود، خطاهای موقت دوباره امتحان می‌شوند و حلقه‌های تکراری متوقف می‌شوند. جزئیات در [پنجرهٔ زمینه و سازوکار پایداری](#پنجره-زمینه-و-سازوکار-پایداری) آمده است.
- **ادامهٔ خودکار کار:** اگر مدل وسط کار متوقف شود—پس از اعلام مرحلهٔ بعد، نوشتن «بخش ۱ از ۳»، پرسیدن اینکه ادامه دهد یا قطع شدن اتصال—از آن خواسته می‌شود کار را ادامه دهد تا مجبور نباشید «ادامه بده» بنویسید. بخش [ادامهٔ خودکار](#ادامه-خودکار) را ببینید.
- **پیوست تصویر، PDF، فایل‌های Office و متن:** برای مدل‌هایی که قابلیت دیدن ندارند، متن فایل، توصیف تولیدشده توسط ارائه‌دهنده‌ای دیگر یا پیامی روشن دربارهٔ محدودیت در اختیارشان قرار می‌گیرد. صفحات PDF با استفاده از قطعه‌های pdf.js بازسازی می‌شوند (از جمله متن فارسی و دیگر زبان‌های راست‌به‌چپ) و فایل‌های طولانی بنا به درخواست صفحه‌به‌صفحه خوانده می‌شوند. بخش [پیوست‌ها](#پیوستها) را ببینید.
- **قابلیت کپی همه‌چیز:** پیام‌ها قابل انتخاب‌اند، هر پیام دکمهٔ کپی و منوی راست‌کلیک دارد و کل گفتگو به‌صورت Markdown کپی می‌شود.

## نیازمندی‌ها

- Obsidian نسخهٔ **1.7.2** یا جدیدتر؛ این مقدار در `minAppVersion` افزونه تعریف شده است.
- نسخهٔ دسکتاپ Obsidian؛ مقدار `isDesktopOnly` برای Agenter فعال است.
- کلید API برای دست‌کم یکی از ارائه‌دهندگان پشتیبانی‌شده یا نصب محلی Ollama.

## نصب

### از طریق افزونه‌های انجمن

پس از ثبت Agenter در فهرست افزونه‌های انجمن Obsidian:

1. **Settings → Community plugins** را باز کنید.
2. **Browse** را انتخاب کنید و **Agenter** را جست‌وجو کنید.
3. **Install** و سپس **Enable** را انتخاب کنید.

### نصب دستی

1. از [آخرین انتشار](../../releases/latest)، فایل `agenter-<version>.zip` یا سه فایل جداگانهٔ `main.js`، `manifest.json` و `styles.css` را دریافت کنید.
2. پوشهٔ زیر را در Vault خود بسازید:

   ```text
   .obsidian/plugins/agenter/
   ```

3. فایل ZIP را در این پوشه استخراج کنید یا سه فایل را در آن کپی کنید.
4. Obsidian را دوباره راه‌اندازی یا بارگذاری کنید.
5. از **Settings → Community plugins** افزونهٔ **Agenter** را فعال کنید.

برای آزمایش نسخه‌های پیش از انتشار، می‌توانید مخزن را با [BRAT](https://github.com/TfTHacker/obsidian42-brat) نیز نصب کنید.

## راه‌اندازی

1. **Settings → Agenter** را باز کنید.
2. یک ارائه‌دهنده اضافه کنید یا موردی را ویرایش کنید.
3. نشانی پایه، کلید API و مدل را وارد کنید؛ یا برای Cloudflare Workers AI روی **Set up** بزنید تا این اطلاعات به‌صورت خودکار شناسایی شوند.
4. با **Test connection & fetch models** اتصال را بررسی کنید.
5. دامنهٔ زمینهٔ پیش‌فرض را انتخاب کنید و گزینه‌های تأیید ابزارها را مرور کنید.

کلیدهای API در فایل دادهٔ افزونهٔ Obsidian یعنی `data.json` به‌صورت متن ساده ذخیره می‌شوند؛ مانند دیگر افزونه‌های Obsidian. این فایل را در مخزن ثبت نکنید و با دیگران به اشتراک نگذارید.

## استفاده

- از پالت فرمان، **Agenter: Open chat in right sidebar** را اجرا کنید یا روی آیکون نوار ابزار بزنید.
- کنترل سربرگ بین حالت نوار کناری و پنجرهٔ شناور جابه‌جا می‌شود.
- متنی را در یادداشت انتخاب کنید تا پنجرهٔ زمینه‌ای باز شود، یا فرمان **Agenter: Run AI action on selection** را اجرا کنید.
- برچسب زمینه در کادر نوشتن، زمینه را بین یادداشت، پوشه، کل Vault و بدون زمینه تغییر می‌دهد.
- برای پرامپت‌های ذخیره‌شده، `/` را تایپ کنید یا از **AI Actions** استفاده کنید.

### پنجرهٔ شناور زمینه‌ای

جایگاه آن را در **Settings → Agenter → Chat → Contextual popover** انتخاب کنید:

| تنظیم | عملکرد |
| --- | --- |
| **Show on selection** | آن را غیرفعال کنید تا پنجره مزاحم نباشد؛ سپس از پالت فرمان یا منوی ویرایشگر بازش کنید. |
| **Placement → Follow the selection** | کنار نشانگر باز می‌شود و اگر پایین آن فضا نباشد، به بالای آن منتقل می‌شود. |
| **Placement → Fixed spot** | همیشه در نقطه‌ای ثابت باز می‌شود و دکمه‌ای برای بازگرداندن آن به گوشهٔ پایین سمت راست دارد. |

معمولاً نیازی نیست این تنظیم را دستی تغییر دهید: سربرگ پنجره را بکشید و در جای دلخواه رها کنید؛ حالت به *Fixed spot* تغییر می‌کند و موقعیت جدید به خاطر سپرده می‌شود. دکمهٔ سنجاق در سربرگ بین دو حالت جابه‌جا می‌شود.

با کلیک روی شمارش واژه‌ها، متن انتخاب‌شده گسترش می‌یابد. دکمهٔ پنل کار را به گفتگوی اصلی منتقل می‌کند: اگر هنوز پرسشی مطرح نکرده‌اید، متن انتخاب‌شده را منتقل می‌کند؛ در غیر این صورت کل گفتگو را.

### تأیید ابزارها

ابزارهای فقط‌خواندنی بدون تأیید جداگانه اجرا می‌شوند. ابزارهایی که Vault را تغییر می‌دهند، پیش از اجرا کارت تأیید نشان می‌دهند؛ این کارت در همان محیطی ظاهر می‌شود که استفاده می‌کنید. انتقال یادداشت به سطل زباله همیشه به دو کلیک آگاهانه نیاز دارد.

ابزارهای فایل فقط به Vault فعلی دسترسی دارند و مسیرهای داخلی محافظت‌شده را نمی‌پذیرند. ابزارهای شبکه جدا هستند و فقط زمانی اجرا می‌شوند که گفتگو به آن‌ها نیاز داشته باشد.

## پنجرهٔ زمینه و سازوکار پایداری

Agenter محدودیت مستقلی برای طول پاسخ تعیین نمی‌کند. گزینهٔ **Settings → Agenter → Chat → Answer length limit** به‌طور پیش‌فرض خالی است؛ یعنی حالت *auto*. هر درخواست تا بیشترین مقداری که مدل با توجه به محتوای فعلی پنجره می‌تواند تولید کند، ادامه می‌یابد. فقط برای محدود کردن هزینه این گزینه را پر کنید. اگر از نسخه‌ای ارتقا می‌دهید که مقدار پیش‌فرض قدیمی 4096 را ذخیره کرده بود، این مقدار به حالت خودکار بازنشانی می‌شود.

### نوار زمینه

نوار بالای کادر نوشتن (و در پنجرهٔ شناور زمینه‌ای) سهم استفاده‌شده از پنجره، اعداد و علامت آغاز فشرده‌سازی را نشان می‌دهد. با پر شدن پنجره، رنگ آن از زرد به نارنجی و قرمز تغییر می‌کند و درصد را همیشه به‌صورت متنی نیز نمایش می‌دهد؛ بنابراین رنگ تنها نشانه نیست. علامت **≈** در ابتدای مقدار یعنی عدد تخمینی Agenter است. پس از هر پاسخ، این مقدار با شمارشی که ارائه‌دهنده گزارش می‌کند جایگزین می‌شود و از آن پس تخمین برای همان مدل اصلاح خواهد شد.

روی نوار کلیک کنید تا محتوای پنجره را ببینید: دستورالعمل‌ها، ابزارها، گفتگو و متن در حال نوشتن؛ همچنین منبع اندازهٔ پنجره، طول احتمالی پاسخ بعدی و دکمه‌های **Compact now** و **New chat**.

### سازوکار پایداری چه می‌کند؟

برخی مدل‌ها در حلقهٔ گفتگوی ساده به دلایلی که با مدیریت مناسب قابل رفع‌اند، افت عملکرد پیدا می‌کنند یا از کار می‌افتند. Agenter برای هر مدل یک *پروفایل* نگه می‌دارد—اندازهٔ پنجره، بیشترین پاسخ و محدودیت‌های آن—و بر همان اساس عمل می‌کند:

| مشکل | عملکرد Agenter |
| --- | --- |
| اندازهٔ پنجره نامشخص است | به‌ترتیب از مقدار بازنویسی‌شدهٔ شما، خطاهای ارائه‌دهنده، فهرست مدل‌های ارائه‌دهنده (OpenRouter، Gemini، Anthropic، Ollama و `/models`)، جدول مدل‌های شناخته‌شده و سپس مقدار پیش‌فرض ایمن استفاده می‌کند. اطلاعات آموخته‌شده ذخیره می‌شوند. |
| گفتگو از ظرفیت پنجره بزرگ‌تر می‌شود | ابتدا خروجی ابزارهای قدیمی را پاک می‌کند، سپس از خود مدل می‌خواهد دورهای قدیمی را خلاصه کند و در نهایت باقی‌ماندهٔ اضافی را همراه با یادداشت حذف می‌کند. پرسش اخیر و آخرین نتایج ابزار حفظ می‌شوند. |
| نتیجهٔ یک ابزار بیش از حد بزرگ است | ابتدا و انتهای نتیجه را نگه می‌دارد، بخش حذف‌شده را اعلام می‌کند و به مدل می‌گوید چطور بقیهٔ محتوا را درخواست کند. |
| ارائه‌دهنده درخواست را رد می‌کند | دلیل را بررسی می‌کند: محدودیت پنجره یا پاسخ، پارامتر پشتیبانی‌نشده مانند `temperature`، تفاوت `max_tokens` و `max_completion_tokens`، `stream_options` یا ابزارها. سپس درخواست را اصلاح و دوباره امتحان می‌کند، بدون اینکه مزاحم شما شود. |
| محدودیت نرخ، بار زیاد یا قطع اتصال | در صورت وجود، `Retry-After` را رعایت می‌کند یا با فاصلهٔ افزایشی تا پنج بار تلاش می‌کند و این موضوع را اعلام می‌کند. |
| پاسخ به‌دلیل محدودیت قطع می‌شود | از همان نقطه ادامه می‌دهد و بخش‌ها را در یک پیام ادغام می‌کند. |
| مدل فراخوانی ابزار را به‌شکل متن می‌نویسد (Hermes، Mistral، JSON حصاردار یا `<function=…>`) | آن را تشخیص می‌دهد و اجرا می‌کند؛ متن خام روی صفحه نمایش داده نمی‌شود. |
| JSON آرگومان ابزار خراب است | تا جای ممکن آن را اصلاح می‌کند؛ در غیر این صورت خطا را به مدل توضیح می‌دهد و از آن می‌خواهد دوباره تلاش کند. |
| مدل از ابزارهای بومی پشتیبانی نمی‌کند | به‌جای آن، شرح ابزارها را در پرامپت قرار می‌دهد. |
| پاسخ خالی یا فراخوانی تکراری | دو بار از مدل می‌خواهد پاسخ دهد؛ پس از سه فراخوانی یکسان هشدار می‌دهد و در ششمین بار از آن می‌خواهد با اطلاعات موجود پاسخ دهد. |
| مدل وسط کار متوقف می‌شود | از آن می‌خواهد ادامه دهد؛ بخش [ادامهٔ خودکار](#ادامه-خودکار) را ببینید. |
| تاریخچهٔ نامعتبر یا ناسازگار | هر فراخوانی ابزار را با نتیجه‌اش جفت می‌کند، شناسه‌ها را یکتا می‌کند، دورهای خالی را حذف می‌کند و تضمین می‌کند اولین دور از طرف کاربر باشد؛ مواردی که APIهای سخت‌گیرتر رد می‌کنند. |
| تفاوت‌های اختصاصی ارائه‌دهندگان | شکل پیام‌های Anthropic و Gemini، رفت‌وبرگشت مدل‌های استدلالی (`reasoning_content` و `thoughtSignature`)، قالب طرح‌وارهٔ Gemini و API بومی Ollama همراه با `num_ctx` واقعی را مدیریت می‌کند. |

Ollama برای کل پنجره‌ای که از آن درخواست می‌شود حافظه رزرو می‌کند؛ بنابراین Agenter حداکثر ۳۲ هزار توکن درخواست می‌کند، مگر اینکه گزینهٔ **Ollama: use the model's whole context** را فعال کنید.

همهٔ این قابلیت‌ها را می‌توان در بخش **Context and reliability** تنظیمات و منوی مدل غیرفعال یا تنظیم کرد. منوی مدل گزینه‌ای برای تعیین دستی اندازهٔ پنجره نیز دارد. اگر مدل همچنان رفتار نامناسبی دارد، گزینهٔ **Copy harness report** در تنظیمات، پنجرهٔ جزئیات یا پالت فرمان، گزارش کارهای Agenter و اطلاعات شناخته‌شده دربارهٔ مدل را کپی می‌کند؛ از جمله تلاش‌های مجدد، اصلاح‌ها، فشرده‌سازی‌ها و محدودیت‌های آموخته‌شده. می‌توانید این گزارش را در یک مسئلهٔ GitHub قرار دهید.

### ادامهٔ خودکار

مدل‌ها به دلایل مختلف زودتر از موعد متوقف می‌شوند. سازوکار پایداری هر مورد را مدیریت می‌کند تا مجبور نباشید «ادامه بده» بنویسید:

| اتفاق | عملکرد Agenter |
| --- | --- |
| پاسخ به سقف خروجی مدل رسیده است؛ حتی اگر مدل با وجود مصرف تمام توکن‌های مجاز وضعیت را «stop» اعلام کند | از مدل می‌خواهد دقیقاً از همان واژه‌ای که متوقف شده ادامه دهد؛ حداکثر تا ۱۲ بخش و سپس همه را در یک پیام ادغام می‌کند. |
| اتصال وسط پاسخ قطع می‌شود | محتوای دریافت‌شده را نگه می‌دارد و از مدل می‌خواهد از همان‌جا ادامه دهد، نه اینکه همه‌چیز را دوباره بنویسد. |
| مدل مرحلهٔ بعد را اعلام می‌کند و متوقف می‌شود (مثلاً «اول بخش‌های میانی را می‌نویسم»)، می‌نویسد «بخش ۱ از ۳» یا می‌پرسد «ادامه بدهم؟» | به آن می‌گوید همان پاسخ را ادامه دهد و کار را انجام دهد؛ حداکثر چهار بار پشت‌سرهم. اگر ادامه تقریباً چیز تازه‌ای اضافه نکند، متوقف می‌شود. اگر مدل پرسشی مطرح کرده باشد که واقعاً به پاسخ شما نیاز دارد، دخالت نمی‌کند. |
| مدل استدلالی تمام سقف خروجی را صرف فکر کردن می‌کند | از آن می‌خواهد کوتاه‌تر فکر کند و پاسخ دهد. |
| مدل یک فراخوانی ابزار را شش بار تکرار می‌کند | از آن می‌خواهد به‌جای پایان یافتن با خطا، با اطلاعات موجود پاسخ دهد. |
| ارائه‌دهنده مرتب درخواست را رد می‌کند یا اتصال پی‌درپی قطع می‌شود | تا هشت بار صبر و تلاش مجدد می‌کند و سپس گزینهٔ **Continue where it stopped** را نشان می‌دهد؛ با یک کلیک کار از همان نقطه ادامه می‌یابد، بدون پیام جدید. |

هر مورد یک خط وضعیت کوتاه در گفتگو نشان می‌دهد. گزینهٔ **Settings → Agenter → Chat → Keep going until the work is done** اعلام ادامه، قطع اتصال، مدل استدلالی و فراخوانی‌های تکراری را غیرفعال می‌کند؛ اما ادامهٔ پاسخ قطع‌شده، تلاش‌های مجدد و دکمهٔ **Continue** همچنان فعال می‌مانند.

## پیوست‌ها

با گیرهٔ کاغذ در کادر نوشتن، یا با کشیدن و رها کردن یا چسباندن فایل، می‌توانید تصویر، PDF، فایل Word، PowerPoint و Excel، فایل متنی و کد و فایل صوتی اضافه کنید. حداکثر اندازهٔ هر فایل ۳۲ مگابایت است. هر فایل یک برچسب دارد که نشان می‌دهد مدل چه چیزی دریافت می‌کند:

| نوع فایل | مدل دارای قابلیت مشاهده | مدل فاقد قابلیت مشاهده |
| --- | --- | --- |
| تصویر | به‌صورت تصویر ارسال می‌شود و اگر بزرگ باشد اندازه‌اش کاهش می‌یابد. | توسط ارائه‌دهندهٔ کمکیِ بینایی توصیف می‌شود؛ این ارائه‌دهنده متن داخل تصویر را نیز استخراج می‌کند. اگر چنین کمکی در دسترس نباشد، صریحاً به مدل گفته می‌شود که تصویر را نمی‌تواند ببیند. |
| PDF | اگر ارائه‌دهنده PDF را مستقیماً بخواند، همان فایل ارسال می‌شود؛ در غیر این صورت متن با موتور PDF خود Obsidian خوانده و بازسازی می‌شود. صفحات اسکن‌شده رسم و نمایش داده می‌شوند. | متن فایل؛ برای صفحات اسکن‌شده، توصیف ارائه‌دهندهٔ کمکی. |
| Word، PowerPoint و Excel | متن، اسلایدها و برگه‌های استخراج‌شده از فایل. | همان محتوا. |
| متن و کد | به‌صورت متن وارد می‌شود. | همان محتوا. |
| صوت | برای ارائه‌دهندگانی که صوت را پردازش می‌کنند (مانند Gemini) ارسال می‌شود. | در صورت امکان توسط ارائه‌دهندهٔ کمکی پیاده‌سازی متنی می‌شود؛ در غیر این صورت به مدل گفته می‌شود فایل صوتی پیوست شده است. |

### PDF چگونه خوانده می‌شود؟

pdf.js متن یکپارچه برنمی‌گرداند، بلکه مجموعه‌ای از قطعه‌های کوچک با مختصات ارائه می‌کند. در فایل‌های واقعی، این قطعه‌ها هنوز متن خوانا نیستند: یک واژهٔ فارسی ممکن است به شکل نویسه‌های جداگانه در حالت نمایشی و به ترتیبی که از چپ به راست رسم شده‌اند برگردد؛ «fl» ممکن است یک قطعهٔ مستقل باشد و یک ردیف جدول از چند قطعه روی یک خط پایه تشکیل شود. Agenter صفحه را بازسازی می‌کند: با استفاده از مختصات، خط‌ها را می‌سازد؛ هر خط را با درنظرگرفتن بخش‌های راست‌به‌چپ و چپ‌به‌راست به ترتیب خواندن درمی‌آورد؛ نویسه‌های نمایشی را به حروف اصلی تبدیل می‌کند؛ پرانتزهای آینه‌شده را اصلاح می‌کند و فاصله‌های عریض را به‌عنوان ستون حفظ می‌کند. به این ترتیب «گزارش فصلی» به‌صورت «گزارش فصلی» می‌رسد، نه حروف جداگانه با ترتیب اشتباه. اگر بیشتر متن یک صفحه از نویسه‌های ناحیهٔ خصوصی یا نویسه‌های جایگزین تشکیل شده باشد (فونتی که نگاشت ندارد)، صفحه به‌عنوان اسکن در نظر گرفته می‌شود.

PDF طولانی که در پنجره جا نمی‌شود، به‌سادگی بریده نمی‌شود. مدل به تعداد صفحه‌های کاملی که جا می‌شوند دسترسی پیدا می‌کند، از صفحه‌های حذف‌شده باخبر می‌شود و دو ابزار برای خواندن بقیه دارد:

| ابزار | عملکرد |
| --- | --- |
| `read_pdf` | برای PDF پیوست‌شده به گفتگو (تا زمانی که گفتگو باز است در حافظه می‌ماند) یا PDF داخل Vault با استفاده از `path`. بدون گزینهٔ دیگر، تعداد صفحات، عنوان و واژه‌های آغازین هر صفحه را برمی‌گرداند (PDF کوتاه به‌طور کامل برگردانده می‌شود). با `pages` مانند `"1-5"` یا `"3,7"`، متن صفحات مشخص‌شده را می‌دهد. با `query`، صفحه‌هایی را که به عبارت اشاره دارند همراه با بخشی از متن پیدا می‌کند؛ گونه‌های مختلف حروف و ارقام فارسی و عربی با هم تطبیق داده می‌شوند. با `view` و `pages`، صفحات را به‌صورت تصویر برای بررسی شکل‌ها، نمودارها و جدول‌ها نمایش می‌دهد. |
| `find_pdfs` | فایل‌های PDF موجود در Vault را بر اساس پوشه یا نام فهرست می‌کند. |

اگر فایل بازشده در Obsidian یک PDF باشد، ابزار `current_note` این موضوع را اعلام می‌کند و به `read_pdf` ارجاع می‌دهد. مسیرهای Vault از همان دامنهٔ دسترسی یادداشت‌ها پیروی می‌کنند؛ اگر PDF خارج از یادداشت، پوشه یا Vault انتخاب‌شده باشد، ابتدا اجازهٔ دسترسی درخواست می‌شود. PDF پیوست‌شده به این اجازه نیاز ندارد.

ارائه‌دهندهٔ کمکی را از **Settings → Agenter → Chat → Describe images for models that cannot see** انتخاب کنید. حالت *Automatic* اولین ارائه‌دهندهٔ پیکربندی‌شده‌ای را انتخاب می‌کند که قابلیت دیدن دارد؛ یا می‌توانید این قابلیت را خاموش کنید. پیوست‌ها نیز بخشی از پنجرهٔ زمینه را اشغال می‌کنند: اندازه‌گیری می‌شوند و اگر جا نشوند، همراه با توضیحی آشکار کوتاه می‌شوند. به مدل گفته می‌شود دربارهٔ محتوایی که دریافت نکرده، حدس نزند.

## کپی کردن متن

تمام محتوای گفتگو را می‌توان با ماوس یا صفحه‌کلید انتخاب کرد. هر پیام دکمهٔ کپی دارد که Markdown همان پیام را کپی می‌کند. با راست‌کلیک روی پیام، گزینه‌های **Copy** برای بخش انتخاب‌شده، **Copy message (Markdown)**، **Copy message (plain text)**، **Select message text** و **Copy whole conversation** در دسترس‌اند. سربرگ نیز دکمه‌ای برای کپی کل گفتگو دارد و رشتهٔ گفتگو به‌شکل Markdown کپی می‌شود. خط‌های تلاش مجدد و فشرده‌سازی نمایش داده می‌شوند اما در تاریخچه ذخیره نمی‌شوند؛ بنابراین وارد متن کپی‌شده نخواهند شد.

## ارائه‌دهندگان

هر ارائه‌دهنده یک قرارداد آداپتور مشترک در `src/api.ts` را پیاده‌سازی می‌کند. انواع مشترک مدل و پیام چندرسانه‌ای در `src/provider-types.ts` قرار دارند.

| ارائه‌دهنده | توضیحات |
| --- | --- |
| OpenAI، Anthropic، Gemini | نشانی پایه، کلید و مدل. |
| OpenRouter | سازگار با OpenAI؛ یک کلید برای مدل‌های متعدد. |
| Ollama | مدل‌های محلی، بدون نیاز به کلید. از API بومی Ollama استفاده می‌کند؛ بنابراین اندازهٔ پنجره‌ای که Agenter درخواست می‌کند همان اندازه‌ای است که دریافت می‌کنید. |
| Cloudflare Workers AI | کلاینت بومی با OAuth یا توکن API؛ جزئیات در ادامه. |
| OpenAI-Compatible / Custom | DeepSeek، Qwen، درگاه‌های میزبانی‌شدهٔ شخصی و هر سرویسی که API گفتگوی OpenAI را پیاده‌سازی کند. |

### Cloudflare Workers AI

Agenter کلاینت اختصاصی Cloudflare Workers AI دارد. احراز هویت، شناسایی مدل‌ها و تشخیص قابلیت‌ها در فایل‌های `src/cloudflare.ts` و `src/cloudflare-oauth.ts` پیاده‌سازی شده‌اند.

**اتصال**

در صفحهٔ تنظیمات دو روش وجود دارد:

- **Connect Cloudflare** (OAuth) وب‌سایت Cloudflare را در مرورگر باز می‌کند، صفحهٔ رضایت را نمایش می‌دهد، از طریق بازگشت محلی PKCE به افزونه برمی‌گردد، حساب‌ها را پیدا می‌کند و فهرست مدل‌ها را همگام‌سازی می‌کند. توکن‌ها به‌طور خودکار تمدید می‌شوند و گزینهٔ **Disconnect** مجوز را لغو می‌کند.
- **Set up Workers AI** (توکن API) دستورالعمل رسمی REST API کلادفلر را دنبال می‌کند: توکن از پیش تنظیم‌شدهٔ Workers AI را ایجاد کنید، آن را همراه با Account ID وارد کنید و Agenter پس از اعتبارسنجی، فهرست زندهٔ مدل‌ها را دریافت می‌کند و ذخیره می‌کند.

نیازی نیست نشانی مدل را دستی وارد کنید. نشانی اجرا از Account ID و مدل انتخاب‌شده ساخته می‌شود.

**قابلیت‌های کلاینت**

- شناسایی زندهٔ مدل‌ها از Cloudflare، همراه با حافظهٔ نهان آفلاین فهرست و زمان آخرین همگام‌سازی.
- تشخیص قابلیت بینایی، صوت، تولید تصویر، embedding، استدلال، حالت JSON، فراخوانی ابزار، پاسخ‌دهی جریانی، رایگان یا پولی بودن، تأخیر و وضعیت آزمایشی یا منسوخ‌شده.
- خطاهای خوانا برای اطلاعات دسترسی نامعتبر، محدودیت نرخ، مدل‌های در دسترس‌نبودنی، پایان مهلت و اختلال‌های Cloudflare.
- پاسخ‌دهی جریانی و فراخوانی ابزار از همان مسیر سایر ارائه‌دهندگان، از جمله کارت‌های تأیید.

**مسیر درخواست‌ها**

| نوع مدل | نشانی |
| --- | --- |
| تولید متن | `POST /accounts/{account_id}/ai/v1/chat/completions` |
| وظایف اختصاصی مدل | `POST /accounts/{account_id}/ai/run/@cf/{author}/{model}` |
| طرح‌وارهٔ زندهٔ ورودی و خروجی | `GET /accounts/{account_id}/ai/models/schema?model=@cf/{author}/{model}` |

برای پیوست کردن تصویر یا فایل صوتی از گیرهٔ کاغذ در کادر نوشتن استفاده کنید. مدل‌های بینایی و تبدیل گفتار، فایل را در قالب مستندشدهٔ خود دریافت می‌کنند و خروجی تولید تصویر یا تبدیل متن به گفتار در گفتگو نمایش داده می‌شود.

Workers AI در طرح‌های Free و Paid سرویس Workers، روزانه ۱۰٬۰۰۰ Neurons بدون هزینه ارائه می‌کند. در طرح رایگان، پس از مصرف سهمیهٔ روزانه درخواست‌ها متوقف می‌شوند.

**برای منتشرکنندگان افزونه**

برای توزیع نسخهٔ خودتان با OAuth، به یک کلاینت عمومی Cloudflare OAuth نیاز دارید:

- جریان: Authorization Code با PKCE (S256)
- احراز هویت توکن: `none`؛ کلاینت دسکتاپ عمومی است، بنابراین نباید secret را داخل بسته قرار دهید.
- نشانی بازگشت: `http://127.0.0.1:42813/cloudflare/callback`
- مجوزها: Workers AI Read، Workers AI Edit و Account Settings Read

شناسهٔ Client ID را یک بار در فیلد مخصوص ناشر وارد کنید؛ پس از آن کاربران فقط باید **Connect Cloudflare** را انتخاب کنند.

## حریم خصوصی و دسترسی شبکه

Agenter سرویس هوش مصنوعی ارائه نمی‌کند و درخواست‌ها را از طریق سرویس خودش عبور نمی‌دهد. بسته به ارائه‌دهنده و ابزارهایی که استفاده می‌کنید، ممکن است داده‌ها به این مقصدها ارسال شوند:

- ارائه‌دهندهٔ هوش مصنوعی یا نشانی سفارشی‌ای که پیکربندی کرده‌اید؛
- DuckDuckGo، هنگام اجرای ابزار `web_search`؛
- هر نشانی‌ای که به ابزار `fetch_url` داده شود.

پیش از ارسال یادداشت‌های حساس، سیاست حریم خصوصی ارائه‌دهنده را بررسی کنید و دامنهٔ زمینه را به اندازه‌ای محدود نگه دارید که کار به آن نیاز دارد.

## توسعه

```bash
npm install
npm run dev     # ساخت در حالت نظارت بر تغییرات
npm run build   # بررسی نوع‌ها و ساخت نسخهٔ نهایی
npm test        # اجرای همهٔ آزمون‌ها
```

سازوکار پایداری آزمون‌های اختصاصی خود را دارد. این آزمون‌ها روی سرورهای HTTP شبیه‌سازی‌شده‌ای اجرا می‌شوند که مانند ارائه‌دهندگان مسئله‌دار رفتار می‌کنند (پارامترها را رد می‌کنند، پنجره را سرریز می‌کنند، وسط پاسخ اتصال را قطع می‌کنند یا فراخوانی ابزار را به‌شکل متن می‌نویسند) و همچنین کد واقعی رابط را آزمایش می‌کنند:

| فایل | موارد تحت پوشش |
| --- | --- |
| `test/harness-core.mjs` | تخمین توکن، پروفایل مدل، دسته‌بندی خطا، اصلاح، پاک‌سازی و فشرده‌سازی |
| `test/harness-providers.mjs` | درخواست ارسالی به هر ارائه‌دهنده و نحوهٔ خواندن جریان پاسخ |
| `test/harness-attachments.mjs` | تشخیص و خواندن فایل‌ها و محتوایی که هر نوع مدل دریافت می‌کند |
| `test/harness-pdf.mjs` | بازسازی صفحهٔ PDF از خروجی pdf.js که از PDFهای واقعی در `test/fixtures/` گرفته شده، محدودهٔ صفحات، `read_pdf` و دامنهٔ دسترسی |
| `test/harness-loop.mjs` | کل حلقهٔ عامل از ابتدا تا انتها با سرورهای شبیه‌سازی‌شده: تلاش مجدد، فشرده‌سازی، ادامهٔ خودکار و PDF |
| `test/harness-ui.mjs` | نوار زمینه، اعلان‌ها، کپی، منو و برچسب‌های پیوست |

فایل‌های قابل توزیع عبارت‌اند از `main.js`، `manifest.json` و `styles.css`.

دستور `node test/pdf-real.mjs` یک آزمون اختیاری روی PDFهای واقعی است: Chromium صفحه‌های انگلیسی، فارسی، ترکیبی و فقط تصویری را به PDF چاپ می‌کند و pdf.js واقعی آن‌ها را دوباره می‌خواند. برای فعال شدن آن، دستور `npm i --no-save playwright pdfjs-dist@4` را اجرا کنید؛ اگر وابستگی‌ها نصب نباشند، آزمون از اجرا صرف‌نظر می‌کند.

### پیش‌نمایش‌ها

پوشهٔ `test/` سه محیط آزمایش آفلاین دارد که `styles.css` واقعی را روی متغیرهای پیش‌فرض پوستهٔ Obsidian در `test/obsidian-theme.css` بارگذاری می‌کنند و ساختار DOM افزونه را بازسازی می‌کنند:

| فایل | نمایش | پارامترهای نشانی |
| --- | --- | --- |
| `test/ui-preview.html` | پنل گفتگوی ثابت | `?light`، `?floating` |
| `test/ctx-preview.html` | پنجرهٔ شناور زمینه‌ای | `?light`، `?chatting`، `?quoting` |
| `test/meter-preview.html` | نوار زمینه، پنجرهٔ آن، اعلان‌ها و برچسب‌های پیوست؛ همراه با قواعد دکمهٔ خود Obsidian از `test/obsidian-controls.css` که در مرورگر خام وجود ندارد | `?light`، `?open` |

برای بررسی تغییرات ظاهری بدون بارگذاری مجدد Obsidian، هر فایل را در مرورگر باز کنید؛ یا تصاویر همین README را دوباره بسازید:

```bash
npm i --no-save playwright && npx playwright install chromium
node test/render-previews.mjs          # پنل و پنجرهٔ شناور
node test/render-harness-preview.mjs   # نوار زمینه
```

## انتشار نسخه

1. نسخه را در `manifest.json`، `package.json` و `package-lock.json` به‌روزرسانی کنید.
2. نسخه و حداقل نسخهٔ موردنیاز Obsidian را در `versions.json` اضافه کنید.
3. تغییرات را ثبت و ارسال کنید.
4. روی همان commit برچسبی دقیقاً برابر نسخهٔ manifest بگذارید؛ بدون پیشوند `v`:

   ```bash
   git tag 1.7.1
   git push origin 1.7.1
   ```

گردش‌کار بررسی می‌کند که برچسب، manifest، package، lockfile و `versions.json` با یکدیگر سازگار باشند؛ سپس آزمون‌ها را اجرا می‌کند، پروژه را می‌سازد و `main.js`، `manifest.json`، `styles.css` و فایل `agenter-<version>.zip` را منتشر می‌کند که شامل همان سه فایل است.

### انتشار بدون برچسب محلی

همین گردش‌کار از زبانهٔ **Actions** نیز اجرا می‌شود و زمانی مفید است که نتوانید برچسب را از نسخهٔ محلی مخزن ارسال کنید:

| ورودی | نتیجه |
| --- | --- |
| *(خالی)* | فایل ZIP و سه فایل جداگانه را به‌عنوان خروجی اجرای گردش‌کار می‌سازد و بارگذاری می‌کند؛ چیزی برچسب‌گذاری یا منتشر نمی‌شود. |
| **publish** | علاوه بر ساخت، برچسب را بر اساس `manifest.json` ایجاد می‌کند—بنابراین بررسی سازگاری فراداده همچنان الزامی است—و انتشار را با هر چهار فایل ایجاد می‌کند. |
| **target** | شناسهٔ commit یا شاخه‌ای که باید ساخته و برچسب‌گذاری شود. پیش‌فرض، شاخه‌ای است که گردش‌کار از آن اجرا شده؛ برای انتشار از شاخهٔ اصلی، `main` را وارد کنید. |

دستور `gh release create` انتشار موجود را بازنویسی نمی‌کند؛ بنابراین هر نسخه فقط یک بار منتشر می‌شود.

برای دیدن تغییرات هر نسخه، [CHANGELOG.md](CHANGELOG.md) را ببینید.
